# fluidLabAgent 小白使用与原理说明

这份说明假设你会打开终端、复制命令，但不要求你懂后端、数据库或 LangGraph。

## 1. 把系统想成一家实验餐厅

浏览器工作台像点餐屏：你选择实验类型，填写目标，点击提交。

FastAPI 像前台：它接收任务、检查参数、给任务编号，并把查询结果发回浏览器。

LangGraph 像流程表：它规定任务先规划，再发给设备，等设备做完后评价结果。程序重启后，数据库仍记得走到了哪一步。

设备 gateway 像实验室传菜员：设备电脑主动向服务器问“有没有我的任务”。收到任务后，它通过串口控制 Arduino，完成后把结果送回服务器。

桌面 bridge 是 DaVis 电脑上的传菜员。它领取 PIV 任务，再让影刀运行经过人工验证的 DaVis 操作模板。

专业 Agent 像顾问：它可以建议使用哪种测量或分析方法，但电机动作仍要走固定参数检查和 gateway。

## 2. 一项任务怎么流动

```text
浏览器提交任务
      ↓
FastAPI 检查角度、速度等参数
      ↓
LangGraph 生成一个允许执行的工具计划
      ↓
数据库同时保存任务和待执行操作
      ↓
设备 gateway 或桌面 bridge 主动领取操作
      ↓
Arduino / 影刀执行，并返回 DONE 或失败
      ↓
LangGraph 保存结果，形成一条实验记忆
      ↓
浏览器显示状态、结果和模拟曲线
```

主动领取的好处是：服务器不需要直接进入仪器电脑，也不用把 Arduino 串口暴露到网络上。

## 3. 三种任务

### 翼板造风场

输入翼板角度、运动速度、目标风速和目标湍流度。当前模拟器生成示意风速；接上设备后，gateway 将角度和速度转换为 Arduino 命令。将来可加入多个翼板轴、600 多个风扇分区和强化学习策略。

### PIV 拍摄

输入图像对数量。真实模式下，桌面 bridge 把任务交给固定的 `davis_capture_v1` 影刀模板。模板应完成打开项目、检查界面、拍摄/导出和结果回报。

### 流动控制

接口与翼板控制共用设备 gateway。将来可接合成射流、等离子体、吹吸气或其他执行器，并把传感器反馈交给 PID、MPC 或强化学习策略计算下一动作。

## 4. LangGraph 原理

主逻辑在 `src/labagent/platform.py`。任务状态为：

```text
queued -> planned -> waiting -> completed
                              -> failed
                              -> unknown
```

`unknown` 表示设备可能已动作，但完成消息丢失。系统会停止自动派发同类设备任务，等待人员现场检查，避免重复运动。

这一版每次调度只推进一个阶段并写入数据库。它适合分钟级实验，因为程序中途关闭也能恢复。

## 5. Arduino 串口协议

gateway 发送一行 JSON：

```json
{"v":1,"id":"任务编号:operation","command":"MOVE","angle_deg":5,"rate_deg_s":2}
```

Arduino 固件完成后回复：

```json
{"id":"任务编号:operation","status":"DONE","actual_angle_deg":5}
```

失败时回复：

```json
{"id":"任务编号:operation","status":"ERROR","message":"limit switch active"}
```

`id` 防止把上一次命令的回复误当成本次结果。Arduino 固件还需要实现急停、限位、回零、看门狗和实际位置反馈。上位机没有收到 `DONE` 时不会盲目重试。

## 6. 影刀 RPA 接口

影刀的版本、账户权限和外部启动接口还没有确认，所以项目没有虚构影刀官方 URL。`bridge.py` 规定了实验室自己的简单接口：

```json
{"operation_id":"任务编号:operation","template":"davis_capture_v1","parameters":{"image_pairs":10}}
```

影刀适配服务执行完后应返回同一个 `operation_id` 和 `status: completed`。如果影刀支持开放 API，就让适配服务调用官方 API；如果只能人工启动，可以让影刀流程轮询本地待办文件或本地 HTTP 服务。确认影刀能力后再实现这一小段适配代码。

## 7. 短期状态和长期记忆

任务表记录当前任务的状态、计划、操作和结果，相当于短期记忆。任务结束后生成一条实验记忆，记录场景、目标、执行模式和结果。模拟结果会带有 `simulated: true`，不能当成真实实验规律。浏览器可以查看和删除记忆。

将来接 PostgreSQL 后，可增加审核字段、适用工况、标定版本、数据文件链接和向量检索。只有人工审核通过的真实实验经验才适合给 Agent 复用。

## 8. 第一次使用

1. 按 README 启动服务。
2. 浏览器打开 `http://127.0.0.1:8000`。
3. 选择“多风扇 / 翼板造风场”和“本机模拟”。
4. 角度填 `5`，速度填 `2`，点击“提交任务”。
5. 观察状态从排队变为完成，再查看模拟风速曲线和 JSON 结果。

## 9. 真机接入前需要提供的信息

- Arduino：板卡、串口、驱动器、步进/伺服方式、脉冲参数、限位和编码器。
- 翼板：轴数、角度和速度范围、回零方式、机械干涉范围和安全姿态。
- 影刀：版本、Windows 版本、授权、外部启动方式和结果回传方式。
- DaVis：版本、项目格式、拍摄流程、导出格式和宏/API 能力。

拿到这些信息后，主要修改 `bridge.py` 和 Arduino 固件；浏览器、API 和 LangGraph 状态流程不需要推倒重写。
