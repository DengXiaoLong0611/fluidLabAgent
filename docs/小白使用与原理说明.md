# fluidLabAgent 小白使用与原理说明

> 适合只会打开终端、复制命令的读者。先用模拟模式学习，不要直接连接真实电机、激光器或相机。

## 先记住三句话

1. **浏览器只是控制面板**，真正的任务状态保存在后端数据库里。
2. **停止 Agent 不等于停止电机**；发现机械危险时，第一动作永远是按现场实体急停。
3. 当前版本完成了软件流程和模拟验证，**尚未与真实 Arduino、DaVis、影刀和实验设备联调**。

## 2. 整个系统像什么

可以把它想成一家实验餐厅：

| 软件部分 | 像什么 | 负责什么 |
| --- | --- | --- |
| 浏览器 Dashboard | 点餐屏和监控屏 | 创建任务、看进度、人工干预、请求停止 |
| FastAPI | 前台 | 接收 HTTP 请求、检查输入、返回 JSON |
| LangGraph | 流程表 | 决定先做哪个节点、下一步走哪里 |
| SQLite/PostgreSQL | 工作记录本 | 保存任务、操作、日志、记忆和用量 |
| Device Gateway / Bridge | 设备传达员 | 主动领取命令，连接 Arduino 或传感器电脑 |
| Desktop Bridge | 桌面传达员 | 把允许的任务交给影刀/DaVis 适配流程 |
| Arduino | 设备控制器 | 读取串口命令，控制电机驱动器并返回结果 |
| LLM Agent | 科学顾问 | 提供建议；不直接获得电机控制权 |

## 3. 三类实验任务

### 3.1 多风扇与翼板造风场

输入翼板角度、运动速度、目标风速和目标湍流度。后续真机版可扩展为：

```text
目标风场
  -> 策略选择 600 多个风扇分区和翼板角度
  -> 安全限幅
  -> 下发动作
  -> 热线/风速仪/PIV 测量
  -> 计算误差或强化学习奖励
  -> 决定下一次动作
```

当前网页表单使用一个简化翼板参数，`fan_count_assumption: 600` 只是场景假设，不表示已经控制了 600 台风扇。

### 3.2 PIV 拍摄

输入图像对数量。真机时由 Desktop Bridge 调用经过人工验证的 `davis_capture_v1` 影刀模板。模板可以负责打开 DaVis 项目、检查指定界面、触发经过许可的步骤、导出结果并回报状态。

激光和相机触发必须另有硬件互锁。RPA 看到按钮并不等于实验条件安全。

### 3.3 主动流动控制

未来可连接合成射流、吹吸气、等离子体或其他执行器。控制算法可以是 PID、MPC、贝叶斯优化或强化学习，但所有算法输出都必须先经过相同的安全层，再交给设备 Gateway。

## 4. 一项任务怎样流动

```text
浏览器 POST /api/tasks
        ↓
FastAPI + Pydantic 检查参数
        ↓
SQLite 保存 queued 任务
        ↓
LangGraph: Plan 选择允许的工具
        ↓
LangGraph: Dispatch 创建设备操作
        ↓
Bridge 主动 Claim 操作
        ↓
Arduino / 影刀适配器执行
        ↓
Bridge 回报 completed / failed
        ↓
LangGraph: Evaluate 保存结果和实验记忆
```

每次调度只推进一个业务节点，执行后马上写数据库。因此服务中途关闭时，任务不会只存在于内存里。

## 5. FastAPI 到底是什么

### 5.1 API 是什么

API 是两个程序约定好的说话方式。浏览器说：

```http
POST /api/tasks
Content-Type: application/json
```

并带上实验参数。后端回答一个 JSON 任务对象。浏览器和后端不需要知道对方内部如何写，只要都遵守这个约定。

### 5.2 FastAPI 是什么

FastAPI 是 Python 的 Web 后端框架。主文件是 `src/labagent/api.py`。例如：

```python
@app.post("/api/tasks", status_code=201)
def submit(body: Submission):
    return store.create(body.model_dump(mode="json"))
```

逐句理解：

- `@app.post(...)`：下面这个函数负责接收一个 HTTP POST 请求。
- `body: Submission`：请求内容必须符合 `Submission` 规定的形状。
- `status_code=201`：成功创建新任务时返回 201。
- `store.create(...)`：把经过检查的任务交给平台层保存。
- `return`：FastAPI 自动把 Python 字典变成 JSON。

### 5.3 Pydantic 为什么重要

`Parameters` 是输入检查表：

```python
angle_deg: float = Field(default=0, ge=-30, le=30)
rate_deg_s: float = Field(default=5, gt=0, le=10)
```

`ge=-30` 是“大于等于 -30”，`le=30` 是“小于等于 30”。网页即使被绕过，后端仍会拒绝 90° 这样的非法值。注意：这些只是当前软件示例范围，真机范围必须依据机械设计重新标定。

## 6. LangGraph 流程和核心代码

浏览器任务真正使用的图在 `src/labagent/platform.py`。`src/labagent/graph.py` 是较早的单场景演示图，便于独立测试算法；两者不要混淆。

### 6.1 状态是什么

```python
class Tick(TypedDict, total=False):
    task_id: str
    phase: str
```

`TypedDict` 表示这个字典预期有哪些键。LangGraph 节点之间传递的是 `state`，这里最重要的是 `task_id`。

任务业务状态是：

```text
queued -> planned -> waiting -> completed
                              -> failed
                              -> unknown
```

- `queued`：刚创建，等待规划。
- `planned`：已选择工具，等待生成设备操作。
- `waiting`：等待模拟器或 Bridge 返回结果。
- `completed`：成功完成。
- `failed`：明确失败。
- `unknown`：设备可能动作过，但回执丢失，必须人工核对。

### 6.2 图是怎样搭起来的

核心代码等价于：

```python
graph = StateGraph(Tick)
graph.add_node("inspect", self.inspect)
graph.add_node("plan", self.plan)
graph.add_node("dispatch", self.dispatch)
graph.add_node("evaluate", self.evaluate)
graph.add_edge(START, "inspect")
graph.add_conditional_edges(
    "inspect",
    lambda state: state["phase"],
    {
        "queued": "plan",
        "planned": "dispatch",
        "waiting": "evaluate",
        "done": END,
    },
)
self.graph = graph.compile()
```

逐句理解：

- `StateGraph(Tick)`：创建一张传递 `Tick` 状态的图。
- `add_node("plan", self.plan)`：登记一个名为 `plan` 的节点，运行时调用 `self.plan`。
- `START`：图的入口。
- `add_conditional_edges`：根据 `phase` 选择不同的下一节点，像程序里的岔路口。
- `END`：本次图运行结束。
- `compile()`：检查并编译图，得到可以执行的对象。
- `graph.invoke({"task_id": ...})`：真正跑一次图。

本项目一次 `invoke` 只推进一个业务节点。这是故意的：完成一个节点就落盘，下一次调度再继续，更适合慢速物理实验。

### 6.3 Plan、Dispatch、Evaluate 各做什么

`plan` 根据场景选择白名单工具：

```python
templates = {
    "field_generation": "flap.set",
    "piv": "davis.capture",
    "flow_control": "flow.set",
}
```

LLM 即使给出建议，也不能创造任意工具名。

`dispatch` 把计划变成 `operation`。设备操作与任务分开保存，所以可以记录是谁领取、何时超时、结果是否未知。

`evaluate` 检查操作状态，保存结果，并形成一条待审核实验记忆。

### 6.4 节点监控怎样实现

调度器执行节点前记下 `started_at`，完成后记下 `ended_at`，两者相减得到 `duration_ms`。每个 `node_run` 保存：

```json
{
  "node": "plan",
  "status": "completed",
  "duration_ms": 1.23,
  "input": {"task_status": "queued"},
  "output": {"task_status": "planned"}
}
```

Dashboard 的“流程监控”只是读取这些记录并画出来，不是在浏览器里重新执行 LangGraph。

## 7. 人工干预和三种停止

### 7.1 暂停流程

点击“暂停流程”后，任务的 `control_state` 变成 `paused`，调度器不再推进它。当前版本是**节点间暂停**：已经开始的同步节点会先结束。

### 7.2 继续并人工补充

只有暂停任务可以继续。输入的文字被写入 `interventions` 和日志，再把 `control_state` 改回 `running`。它适合记录“先检查标定板”等人工决定。

当前确定性模板只保存这段文字，还没有让所有后续节点自动修改计划。以后接 LLM 时，应把已审核干预作为受信任上下文输入规划节点。

### 7.3 停止 Agent / LLM

“停止 Agent”会阻止后续图节点和模型调用，并取消尚未被设备领取的操作。它是**软件软停止**。

当前版本不能强制杀掉一个已经在 Python 线程中执行的 LLM HTTP 请求；按钮要等当前调用返回后生效。正式版应给模型请求设置短超时和可取消任务，并把长时间工作拆成多个小节点。

### 7.4 设备急停

“设备急停”创建 `system.emergency_stop` 操作，优先于普通设备操作被 Gateway 领取。串口命令是 `STOP`，不是 `MOVE`。

网页出现“已排队”仅说明服务器记录了请求。完整确认链是：

```text
网页已请求 -> Gateway 已领取 -> Arduino 已确认 -> 驱动器已禁用 -> 现场确认停止
```

本系统不能替代实体急停、限位开关、驱动器 STO 和独立看门狗。

还要特别注意：当前 Python Bridge 是单进程串行执行。如果它正阻塞等待一个 `MOVE` 的完成回复，就不能保证网页 `STOP` 立刻写入同一串口。真机版必须把急停做成独立硬线或控制器内可抢占逻辑；不能把浏览器按钮当作唯一急停手段。

## 8. 为什么需要 Device Gateway

如果 FastAPI 直接打开实验室电脑的串口，会有几个问题：

- 服务器不一定在连接 Arduino 的电脑上。
- 把串口直接暴露到网络很危险。
- 网络断线时，服务器不知道设备到底有没有完成动作。
- DaVis、影刀和 Arduino 的调用方式完全不同。

所以本项目采用主动领取：Gateway 每秒向 FastAPI 问“有没有我的任务”。实验室电脑只需要主动访问服务器，不需要让服务器远程控制整个桌面。

启动模拟 Gateway：

```bash
uv run labagent-bridge --kind device --adapter simulation
```

启动 Arduino 串口 Gateway：

```bash
uv run labagent-bridge \
  --kind device \
  --adapter serial \
  --port /dev/cu.usbmodemXXXX
```

Bridge 会发送心跳，Dashboard 才把对应组件显示为在线。超过 5 秒收不到新心跳时，页面会显示“心跳已过期”。

## 9. Arduino 串口协议是什么

### 9.1 串口是什么

串口是电脑和微控制器按顺序传字节的通信方式。本项目暂定：

- 波特率：`115200`
- 数据格式：UTF-8 JSON Lines
- 一条消息一行，以换行符 `\n` 结束
- 协议版本：`v: 1`

JSON 的好处是人能直接看懂，Python 和 Arduino 也容易解析。缺点是比二进制协议大；目前命令频率低，先用可调试性更好的 JSON。

### 9.2 运动命令

```json
{"v":1,"id":"任务号:operation","command":"MOVE","angle_deg":5,"rate_deg_s":2}
```

### 9.3 急停命令

```json
{"v":1,"id":"emergency:编号","command":"STOP","target":"all","reason":"operator request"}
```

### 9.4 Arduino 回复

成功：

```json
{"id":"任务号:operation","status":"DONE","actual_angle_deg":5}
```

失败：

```json
{"id":"任务号:operation","status":"ERROR","message":"limit switch active"}
```

`id` 用来把回复和命令配对。上位机没有收到 `DONE` 时不会自动重发运动命令，因为设备可能已经动过，只是回复丢了。

真机前，Arduino 固件必须实现 STOP 高优先级抢占、限位、回零、看门狗、编码器反馈、重复命令去重和上电安全状态。仓库当前没有 Arduino 固件，因为板卡、驱动器和接线尚未确定。

## 10. 影刀 RPA 与 DaVis 怎样连接

RPA 是让软件模拟人点击桌面界面的工具。它适合没有稳定 API 的商业软件，但比官方 API/宏更脆弱：窗口位置、分辨率、弹窗和软件升级都可能让流程失效。

优先级建议：

```text
DaVis 官方 API/宏 > DaVis 命令行 > 影刀受控模板 > 任意坐标点击
```

影刀版本和开放接口还没有确认，所以 `bridge.py` 没有虚构官方地址，而是定义实验室自己的 HTTP 适配契约：

```json
{
  "operation_id": "任务号:operation",
  "template": "davis_capture_v1",
  "parameters": {"image_pairs": 10}
}
```

启动 Desktop Bridge：

```bash
uv run labagent-bridge \
  --kind desktop \
  --adapter rpa \
  --endpoint http://127.0.0.1:9001/run
```

这里的 `9001/run` 是未来在 DaVis/影刀电脑上实现的实验室适配服务，不是影刀官方 URL。适配服务应检查固定模板名，绝不能接受任意“点击某坐标”的远程命令。

## 11. Dashboard 每一页看什么

### 系统总览

看活动任务、暂停数、Token、费用和六个组件状态。FastAPI 正常只表示网页后端正常，不表示 Arduino 在线。

### 流程监控

看任务状态、节点耗时、输入输出、错误和人工干预。这里可以暂停、继续或停止 Agent。

### 实验任务

创建和查看三类任务、计划、结果、事件时间线和模拟曲线。

### 设备与急停

看 Gateway、Arduino 和 RPA 心跳，选择停止目标并请求软件急停。现场实体急停优先级更高。

### Agent 与模型

选择 provider、模型名称、温度和最大 Token。温度越低，回答通常越稳定；实验规划建议从 `0` 到 `0.3` 开始。

API Key 不会存入网页或数据库，只从服务器环境变量读取。

#### 本机 Ollama：现在可以实际使用

本项目已支持本机 Ollama 的聊天 API。电脑不需要 API Key；先确保 Ollama 正在运行，再在“Agent 与模型”页面选择 `Ollama 本地模型`，填写已下载的模型名，例如 `qwen2.5:1.5b`。

这个本地模型只扮演“实验规划顾问”：它可以给出测量检查、分析方法和证据缺口建议；不能直接控制 Arduino、电机、翼板或 RPA。模型没有响应时，系统会记录一条 `model.advice.failed` 日志，并继续使用确定性规划，不会因为模型离线而中断任务。

对于 8 GB 内存的 M1，`qwen2.5:1.5b` 适合短建议、中文摘要和固定格式检查。它不适合独立判断复杂流体机理，也不应用于未经人工确认的设备控制。

### 日志与设置

显示结构化日志。为了安全，工作台没有任意 Bash 输入框。所谓“命令行显示”被替换为只读日志和白名单诊断，避免浏览器获得服务器任意命令执行权。

### 实验记忆

查看或删除任务结束后形成的经验。当前记忆都是“未审核”，不能自动成为科学结论。

## 12. 模型切换、Token 和费用

当前已实现 Ollama 的本机建议器。Dashboard 仍预留 OpenAI、Anthropic、Google 和 DeepSeek 的配置元数据，但它们的实际客户端适配尚未写入；选择它们不会调用云端 API。

未来接入 DeepSeek 时，API Key 应只写在服务器环境变量，例如：

```bash
export DEEPSEEK_API_KEY="你的密钥"
```

不要把密钥提交到 Git。`.env` 和数据库文件已在 `.gitignore` 中忽略。

Token 近似理解为模型读写文字的计数单位。费用估算通常是：

```text
输入费用 = 输入 Token / 1,000,000 × 输入单价
输出费用 = 输出 Token / 1,000,000 × 输出单价
```

当前 Ollama 会把本机模型回传的输入、输出 Token 和响应耗时自动记录到 Dashboard；本地模型费用固定记为 0。云端模型的价格换算将在对应客户端接入时完成。显示金额始终只是内部估算，不是厂商账单。

## 13. 日志保存在哪里

任务、节点记录、心跳、用量和结构化日志目前都保存在：

```text
labagent.db
```

这是 SQLite 文件。浏览器“日志与设置”页通过 `/api/logs` 读取日志。正式部署建议把 `LAB_DATABASE_URL` 切换为 PostgreSQL，并增加实验文件存储和定期备份。

常用排错命令：

```bash
# 运行测试
uv run pytest -q

# 检查代码风格
uv run ruff check .

# 查看 Arduino 串口（macOS）
ls /dev/cu.*
```

- 翼板/滑轨/转盘的电机、驱动器、Arduino 板卡、引脚和限位。
- 实体急停、STO、看门狗和故障复位流程。
- 热线、风速仪、DAQ 和传感器采样协议。
- DaVis 版本、项目模板、相机/激光互锁和导出方法。
- 影刀版本、开放 API、流程触发和结果回传能力。
- 多模型真实客户端、usage 回写、长期记忆检索和强化学习训练闭环。

## 16. 真机开发顺序

1. **只接一个无负载电机**：确认 STOP、限位、回零和看门狗。
2. **接一个翼板或滑轨**：标定单位、方向、速度和机械边界。
3. **接一个传感器**：验证采样时间戳、质量标记和断线处理。
4. **建立小规模闭环**：先用确定性扫描/PID，不直接上强化学习。
5. **扩展到风扇分区和智能策略**：保留安全层、审批点和完整审计日志。

下一次真机开发需要先整理一张设备表：设备名称、型号、通信方式、安全范围、控制电脑、急停方式和负责人。
